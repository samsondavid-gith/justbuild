Build · Web App  ·  2 of 6

Build the app itself.

Session 3 · 120 min  |  Model: Claude-style app builder - the strongest code model of the two days

This is the one code-heavy build. Replace every [bracket] with your own idea, then feed the builder ONE step at a time - do not paste it all at once. Test each step before the next.

The destination prompt (your app, end to end)
Build me a simple, mobile-first web app for [my business, e.g. "Sunday tiffin subscriptions for PG students"]. It must have a SERVER and a DATABASE so data is saved, and I need a link I can open and share. It does four things, in order: 1. CATALOG - a home page showing my items from the database: each with a name, one image, a price, and a one-line description. [list 3-5 of my items]. 2. CHOOSE & CONFIGURE - tapping an item opens a page to pick options and quantity [e.g. size: half/full, spice: mild/hot], with the total updating live. 3. PAY (STUB) - a checkout that collects name + phone, shows the total, and a "Pay now" button that does NOT take real money - it just marks the order Paid and saves it. Show a note: "Demo payment - no money is charged." 4. TRACK - after paying, show an order number, and a "Track my order" page where a user types the number and sees status: Received -> Preparing -> Ready. Keep it clean and simple, one clear button per screen, works on a basic phone. Fill it with my real items, not placeholder text.

How to use it

  1. Catalog first. Ask only for the catalog page from your database. Test: do all items show, readable on a phone?
  2. Choose & configure. "When I tap an item, let me pick [options] and a quantity, show the running total." Test one item.
  3. Pay stub + save. "Add checkout: name, phone, total, a Pay button that marks the order Paid and saves it - no real money." Place a full order.
  4. Track. "Show an order number, add a Track page that looks it up: Received -> Preparing -> Ready." Copy a number and test it.
  5. Fill it for real, one clean design pass, then save a copy of the working version.
Never put a secret in the page (anyone can read it) - today there is none, because payment is a stub. Trust, then verify: the model is confidently wrong sometimes; test every step.
